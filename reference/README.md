# Reference (frozen)

`bcg-band-bass-charts.html` is the design spec and the seed data: the hand-built
page the product reproduces. It is kept byte-identical to the original artifact
and is not edited. Open it in a browser to see the target look (it loads abcjs
6.4.4 from cdnjs and the fonts from Google Fonts).

- `abc/<id>.abc` — the exact ABC string the reference page builds for each song
  (dumped from the page itself). `packages/chart-core` reproduces these byte for
  byte from `charts/<id>.json`, minus the `%%barsperstaff 4` line (see below);
  `test/golden.test.ts` pins that.
- `songs.json` — the page's `songs[]` array as data, in page order (X:1..7).
- `baseline/` — generated by `npm run baseline -w @lowbook/charts`: each song's
  staff re-rendered from the reference data with the app's abcjs build and font
  files, as exact SVG markup and as PNG. The parity test compares the app's
  staff against these. Regenerate when abcjs, the fonts or the render options
  change, and look at the diff before committing.

## ABC dialect the renderer relies on

```
X:1
M:4/4
L:1/4
Q:1/4=124
K:D clef=bass style=rhythm
P:A
"D"D,, "Em"D,, D,, D,, | D,, D,, D,, D,, | "D/F#"D,, D,, D,, D,, | "G"D,, D,, D,, D,, |
P:B
|: "D"D,, "Em"D,, D,, D,, | D,, D,, D,, D,, | "Bm"D,, D,, D,, D,, | "A"D,, D,, D,, D,, :|
P:C
"N.C. drums"x4 | x4 | "G"D,, D,, D,, D,, | "G"D,, D,, D,, D,, |]
```

- `style=rhythm` on `K:` turns note heads into slashes; `D,,` is just a pitch
  that sits on the staff, its name is never shown.
- A chord symbol goes in quotes immediately before the slash it lands on.
- A bar with no annotation continues the previous chord.
- `x4` is an invisible whole-bar rest (N.C. bars).
- **One source line is one staff line.** The app writes 4 bars per line (the
  reference layout) or 8 when a chart needs it.
- `|:` … `:|` repeat a section; the last bar of the tune ends `|]`.
- **A blank line ends the tune** and renders nothing after it.

## Two things the reference does that the app deliberately does not

1. **`%%barsperstaff 4`.** With this directive abcjs ignores the source line
   breaks and re-flows every N bar lines, and it counts a leading `|:` as one of
   them. The last bar of every repeated section therefore spills onto the next
   line, and Billie Jean and Since U Been Gone end with a one-bar orphan line.
   Without the directive abcjs keeps our line breaks exactly. The lint rejects
   the directive.
2. **Duplicate part labels.** abcjs 6.4.4 (and 6.7.1) prints a repeated
   section's boxed letter again at the start of every later staff line. The app
   removes those duplicates after rendering; the reference page shows them.

Both corrections are applied when the baselines are generated, so "parity" means
the reference's own ABC and data, rendered without those two defects.
